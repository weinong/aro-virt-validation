# 2026-05-08 — Phase 3 TechPreviewNoUpgrade fails on 4.22.0-rc.3 (CRD-before-CR)

> **Note:** This commit also bumps the
> `is_known_bad_techpreview_payload` cutoff from `rc.2` to `rc.3`, so the
> historical "guard returned 0 for rc.3" narrative below is what happened
> *before* the fix. Reproducing this on `rc.3` now requires
> `ALLOW_KNOWN_BAD_TECHPREVIEW_PAYLOAD=true`.

## Summary

Enabling `TechPreviewNoUpgrade` on a freshly-upgraded ARO cluster at OCP
**4.22.0-rc.3** triggers the same "CR applied before CRD" CVO failure the README
documents for 4.22.0-rc.0…rc.2. The repository's known-bad payload guard
(`is_known_bad_techpreview_payload` in `scripts/env.sh`) currently treats only
`ec.*` and `rc.0`/`rc.1`/`rc.2` as bad, so `rc.3` is not blocked and the failure
reaches the cluster.

`featuregate/cluster.spec.featureSet` is now permanently `TechPreviewNoUpgrade`
on this cluster (irreversible). The cluster is otherwise healthy
(`Available=True`, no Degraded COs, both MCPs Updated), but
`ClusterVersion` cannot finish applying the 4.22.0-rc.3 payload because three
TechPreview-gated extension CRDs never come up:

- `criocredentialproviderconfigs.config.openshift.io`
- `dnsnameresolvers.network.openshift.io`
- `osimagestreams.machineconfiguration.openshift.io`

## What happened

1. `./scripts/03-techpreview-setup.sh` patched
   `featuregate/cluster` to `TechPreviewNoUpgrade` (the guard
   `guard_known_bad_techpreview_payload "4.22.0-rc.3"` returned 0).
2. CVO began re-syncing the 4.22.0-rc.3 payload under the new feature set.
3. CVO repeatedly fails at task **33 of 1084**:

   ```
   Could not update criocredentialproviderconfig "cluster" (33 of 1084):
   the server does not recognize this resource, check extension API servers
   ```

4. CVO log (`deploy/cluster-version-operator` in `openshift-cluster-version`):

   ```
   error running apply for criocredentialproviderconfig "cluster" (33 of 1084):
   failed to get resource type: no matches for kind
   "CRIOCredentialProviderConfig" in version "config.openshift.io/v1alpha1"
   ```

5. `oc get crd` confirms none of the three TechPreview extension CRDs are
   installed:

   ```
   $ oc get crd criocredentialproviderconfigs.config.openshift.io
   Error from server (NotFound)
   $ oc get crd dnsnameresolvers.network.openshift.io
   Error from server (NotFound)
   $ oc get crd osimagestreams.machineconfiguration.openshift.io
   Error from server (NotFound)
   ```

6. `Failing` flips between `True` (when CVO retries the bad task) and `False`
   (between retries). The first script run aborted on the first `Failing=True`
   flap; the retry hit the same flap. The persistent state is
   `Progressing=True, Failing=True (intermittent),
   message="...criocredentialproviderconfig \"cluster\" (33 of 1084):
   the server does not recognize this resource..."`.

## Verdict

This is **the same product issue called out in `scripts/env.sh` and the
README**, just on a payload (`4.22.0-rc.3`) that the repo's guard does not yet
flag. CVO orders a TechPreview-gated CR (`CRIOCredentialProviderConfig`) before
the corresponding extension CRD is served, so the payload sync stalls
indefinitely.

This is a **product/CVO ordering bug**, not a configuration mistake on our
side. We should not work around it by hand-applying the missing CRDs (that is
on the project's stop-and-document list).

## State of the cluster

- `featuregate/cluster.spec.featureSet=TechPreviewNoUpgrade` — **irreversible**.
- `ClusterVersion`: `Available=True`, `Progressing=True`, `Failing` flapping,
  desired version `4.22.0-rc.3`, last completed history entry already
  `4.22.0-rc.3`.
- All ClusterOperators `Available=True`, none Degraded.
- `master` and `worker` MCPs `Updated=True`.
- TechPreview extension CRDs not present, so Phases 4–8 of the README cannot
  proceed (the MSHV step explicitly requires `OSImageStream/cluster` and the
  `rhel-10` stream, which depend on `osimagestreams.machineconfiguration.openshift.io`).

## Manual interventions taken

None. The `featuregate` patch is the documented, declarative Phase 3 step;
that is not a workaround.

## Open product issues (do not close)

- **CVO TechPreview ordering on 4.22.0-rc.3**: CVO applies
  `CRIOCredentialProviderConfig/cluster` (task 33 of 1084) before the
  `criocredentialproviderconfigs.config.openshift.io` CRD is served by the
  config extension API server. Same symptom previously seen on
  4.22.0-rc.0…rc.2. Needs to be raised against the 4.22 release / config
  extensions team.
- **`scripts/env.sh` guard was out of date** (fixed in this commit):
  `is_known_bad_techpreview_payload` previously blocked only `ec.*` and
  `rc.0`/`rc.1`/`rc.2`, allowing `rc.3` through. The cutoff has been bumped to
  `rc.3`. The guard will need re-bumping (or replacing with a positive allowlist
  of known-good payloads) when the next bad 4.22 RC is identified.

## Suggested next steps (for the human)
